## TL-001 저장소는 localStorage 키 하나 + 스키마 버전

- **상태**: 채택 · 2026-11-11
- **배경**: 서버 없이 새로고침 후에도 데이터가 남아야 해요. 할 일은 하루 10~20개라 양이 적어요.
- **결정**: `localStorage`의 `task-manager` 키 하나에 `{ version, todos, rules, settings }`를 JSON으로 저장해요.
- **대안**
  - IndexedDB: 용량이 크고 비동기라 좋지만, 이 정도 데이터에는 코드만 복잡해져요.
  - 키를 여러 개로 나누기: 한 번에 같이 바뀌어야 하는 데이터(할 일 + 규칙의 `lastGeneratedDate`)가 따로 저장되다 어긋날 수 있어요.
- **영향**: 구조를 바꿀 때 `version`을 올리고 `storage.js`에 마이그레이션을 추가해야 해요. 브라우저 데이터를 지우면 할 일도 사라져요(나중에 내보내기/가져오기 기능을 고려).

<a id="tl-002"></a>
## TL-002 ES 모듈 사용 → 로컬 서버로 실행

- **상태**: 채택 · 2026-11-11
- **배경**: PRD v0.1에서는 `index.html` 더블클릭으로 실행하는 게 목표였어요. 그런데 기능이 늘면서(알림, 반복, 드래그) 파일을 나누지 않으면 한 파일이 너무 커져요.
- **결정**: `<script type="module">`과 `import/export`로 파일을 나눠요. 대신 로컬 서버(VS Code Live Server 등)로 열어야 해요.
- **대안**
  - 모듈 없이 `<script>` 여러 개를 순서대로 넣기: 더블클릭은 되지만 전역 변수가 섞이고 순서에 의존해서 관리가 어려워요.
  - 파일 하나에 다 넣기: 처음엔 쉽지만 기능 11개를 한 파일에서 찾기 힘들어요.
- **영향**: 어차피 서비스 워커(오프라인·홈 화면 추가)도 `file://`에서 동작하지 않아서, 로컬 서버는 피할 수 없었어요.

<a id="tl-003"></a>
## TL-003 알림은 PWA 서비스 워커로, 서버 없이

- **상태**: 대체됨 → [TL-009](#tl-009) · 2026-11-11
- **배경**: 정해진 시간에 휴대폰 알림을 받고 싶어요. 그런데 서버는 두지 않기로 했어요.
- **확인한 사실**
  - Android Chrome은 페이지에서 `new Notification()`을 막고, 서비스 워커의 `showNotification()`만 허용해요.
  - iOS Safari는 16.4부터, **홈 화면에 추가한 웹 앱**에서만 알림을 허용해요.
  - 서비스 워커와 알림 권한은 HTTPS(또는 localhost)에서만 동작해요.
  - 페이지가 닫히면 자바스크립트 타이머도 멈춰요. 예약 알림을 위한 브라우저 표준(Notification Triggers)은 실험 단계에서 중단됐어요.
- **결정**: PWA로 만들고, 앱이 열려 있는 동안 `setTimeout`으로 예약해서 서비스 워커로 알림을 보내요. 다시 열었을 때 지난 알림은 "놓친 알림" 배너로 보여줘요.
- **대안**: Web Push + 푸시 서버(예: Supabase Edge Functions + 크론). 닫힌 앱에도 정확한 알림이 가능하지만 서버·키 관리가 필요해서 이번 범위에서 빼요.
- **영향**: 앱이 닫혀 있으면 알림이 오지 않을 수 있어요. PRD F9와 TRD 5.7에 한계를 적어 두었어요.

<a id="tl-004"></a>
## TL-004 드래그는 Pointer Events로 직접 구현

- **상태**: 채택 · 2026-11-11
- **배경**: 휴대폰에서 손가락으로 순서를 바꿀 수 있어야 해요.
- **결정**: `pointerdown / pointermove / pointerup`으로 직접 만들어요. 손잡이에서만 시작하고 `touch-action: none`으로 스크롤과 충돌을 막아요.
- **대안**
  - HTML5 Drag and Drop API: 모바일 터치에서 동작하지 않아요.
  - SortableJS 같은 라이브러리: 편하지만 "라이브러리 없이" 원칙과 맞지 않아요.
- **영향**: 자동 스크롤, 키보드 이동(↑/↓)도 직접 만들어야 해요.

<a id="tl-005"></a>
## TL-005 날짜는 로컬 'YYYY-MM-DD' 문자열

- **상태**: 채택 · 2026-11-11
- **배경**: "오늘", "어제"를 비교하는 일이 많아요(이월, 반복, 진행률).
- **결정**: 날짜 키는 `getFullYear() / getMonth() / getDate()`로 만든 로컬 시간 문자열을 써요. 문자열끼리 크기 비교가 그대로 날짜 비교가 돼요.
- **피한 실수**: `new Date().toISOString().slice(0, 10)`은 UTC라서 한국 시간 오전 0~9시에는 어제 날짜가 나와요.
- **영향**: 시간이 필요한 값(`createdAt`, `completedAt`)만 ISO 문자열로 저장해요.

## TL-006 반복은 규칙 + 날짜별 할 일 생성, 반복 할 일은 이월 안 함

- **상태**: 채택 · 2026-11-11
- **배경**: 반복 일정과 미완료 이월이 같이 있으면, 매일 반복하는 일을 못 했을 때 다음 날 같은 할 일이 두 개가 돼요.
- **결정**
  - 규칙(Rule)과 할 일(Todo)을 따로 저장하고, 날짜가 바뀔 때 오늘 몫의 할 일만 만들어요. `lastGeneratedDate`로 중복 생성을 막아요.
  - 반복으로 생긴 할 일은 이월하지 않고, 지난 날짜의 미완료분은 지워요.
- **대안**: 반복 할 일 하나를 계속 재사용하며 완료 상태만 매일 초기화 → 날짜별 완료 기록이 남지 않고 진행률 계산이 꼬여요.
- **영향**: 규칙을 고쳐도 이미 생긴 할 일은 바뀌지 않아요 (PRD F8에 명시).

## TL-009 알림 기능 제거

- **상태**: 채택 · 2026-11-11 (TL-003을 대체)
- **배경**: 문서 검토에서 알림의 한계가 컸어요. 서버가 없으면 앱이 닫혀 있을 때 알림이 오지 않고, iPhone은 홈 화면에 추가해야만 알림이 와요. 이월된 할 일의 알림이 다시 울리지 않는 문제도 발견됐어요.
- **결정**: 알림 기능(PRD F9)을 빼요. `remindAt`, `notifiedAt` 필드와 `features/reminders.js`, 놓친 알림 배너, 서비스 워커의 알림 처리도 함께 뺐어요.
- **대안**: 푸시 서버를 두고 Web Push로 보내기. 정확하지만 서버와 키 관리가 필요해서 이번 범위에 맞지 않아요.
- **영향**: PWA는 홈 화면 추가와 오프라인 사용을 위해 그대로 둬요. 나중에 알림을 다시 넣으려면 PRD에 F9를 되살리고 데이터 버전을 올려야 해요.

<a id="tl-010"></a>
## TL-010 id는 createId()로 만들고 randomUUID가 없으면 대체

- **상태**: 채택 · 2026-11-11
- **배경**: `crypto.randomUUID()`는 HTTPS나 localhost에서만 있어요. 휴대폰에서 PC의 IP 주소(`http://`)로 테스트하면 할 일을 추가하는 순간 오류가 나요.
- **결정**: `core/id.js`의 `createId()`만 써요. `randomUUID`가 있으면 쓰고, 없으면 `Date.now()`와 `Math.random()`을 36진수로 이어 붙여요.
- **대안**: 숫자를 1씩 늘리는 id → 데이터를 지웠다 다시 만들거나 백업을 합칠 때 겹칠 수 있어요.
- **영향**: 다른 파일에서 `crypto.randomUUID()`를 직접 부르지 않아요 (TRD 5.7).

<a id="tl-011"></a>
## TL-011 순서는 0부터 이어지는 정수, 바뀔 때마다 다시 매김

- **상태**: 채택 · 2026-11-11
- **배경**: 새 할 일은 이월된 할 일 바로 아래, 완료 취소는 맨 아래, 드래그는 아무 데나 들어가요. 그런데 `order`를 어떻게 매길지 정해져 있지 않아서 이월 항목과 새 항목이 같은 번호를 갖거나 순서가 뒤섞일 수 있었어요.
- **결정**: 미완료 목록을 배열로 다루고, 끼워 넣거나 옮긴 뒤 매번 `0, 1, 2…`로 다시 매겨요. 순서 계산은 `core/order.js`에 모아요 (TRD 5.4).
- **대안**
  - 소수 순서(두 항목 사이에 1.5 넣기): 다시 매기지 않아도 되지만 소수가 계속 쪼개지고 코드가 읽기 어려워요.
  - 새 할 일에 음수(`최솟값 - 1`) 주기: 맨 위에 넣기는 쉽지만 "이월 항목 바로 아래" 규칙을 만들 수 없어요.
- **영향**: 할 일이 하루 20개 정도라 매번 다시 매겨도 느려지지 않아요. "이월 항목 바로 아래"는 맨 위에 **연속으로** 붙은 이월 항목 기준이라, 사용자가 드래그로 옮긴 순서를 덮어쓰지 않아요.

<a id="tl-012"></a>
## TL-012 1단계 구현에서 정한 core 함수의 세부 동작

- **상태**: 채택 · 2026-11-11
- **배경**: TRD는 함수 이름과 역할만 정해 두었어요. 만들면서 테스트하기 쉽게 몇 가지를 더 정해야 했어요.
- **결정**
  - `createId(cryptoImpl = globalThis.crypto)`: TRD 5.7의 코드에 인자 하나를 더했어요. 브라우저의 `crypto`는 바꿀 수 없어서, 테스트에서 `randomUUID`가 없는 환경(`http://` 접속)을 흉내 내려면 인자로 넘겨야 해요. 앱 코드에서는 인자 없이 불러요.
  - `order.js`의 `insertNew` / `appendLast` / `move`는 받은 배열을 바꾸지 않고 **새 배열**을 돌려줘요. `renumber`만 항목 객체의 `order`를 직접 바꿔요. 그래서 항상 `renumber(insertNew(list, todo))`처럼 이어서 불러요.
  - `move(list, from, to)`의 `to`가 범위를 벗어나면 맨 앞/맨 끝으로 맞춰요.
  - `date.js`에 TRD 5.1에 없던 `fromKey(key)`(날짜 키 → 로컬 자정 `Date`)와 `formatHeaderDate(key)`(`11.11(수)`)를 더했어요.
  - `openSheet({ mode, opener })`: 닫은 뒤 포커스를 돌려줄 요소를 받아요. 휴대폰에서는 탭해도 버튼에 포커스가 가지 않기 때문이에요 (TRD 5.9 보완).
- **대안**: 테스트에서 `globalThis.crypto`를 바꿔 끼우기 → 브라우저에서는 읽기 전용이라 안정적으로 할 수 없어요.
- **영향**: TRD의 함수 표는 그대로 맞고, 이 항목이 세부 동작을 보충해요.

<a id="tl-013"></a>
## TL-013 진행률 반올림과 2단계 화면 세부 규칙

- **상태**: 채택 · 2026-11-11
- **배경**: PRD F5·F6·F2는 큰 동작만 정해 두었어요. 만들면서 애매한 부분이 몇 가지 있었어요.
- **결정**
  - **진행률 %는 반올림하되, 다 끝내지 않았으면 최대 99%** (`core/progress.js`의 `toPercent`). 그냥 반올림하면 199/200이 100%로 보여서 축하 문구가 없는 100%가 생겨요.
  - **진행률은 필터와 상관없이** 오늘의 전체 할 일로 계산해요. 카테고리별 숫자가 따로 있어서 필터별 진행률은 필요 없어요.
  - **수정 시트에서 고른 카테고리는 `lastCategory`(추가 기본값)를 바꾸지 않아요.** 예전 할 일을 정리하다가 다음에 추가할 기본값이 바뀌면 헷갈려요.
  - **빈 상태 문구**: 오늘 할 일이 0개면 진행률 자리에 `할 일을 추가해 보세요 · 0%`를 보여주고, 목록에는 따로 띄우지 않아요. 필터 때문에 목록이 비었을 때만 목록에 `업무 할 일이 없어요`처럼 보여줘요.
  - 필터 탭은 `role="tablist"` 대신 `aria-pressed` 버튼 묶음(`role="group"`)으로 만들었어요. 탭마다 다른 내용 영역(tabpanel)이 있는 게 아니라 같은 목록을 거르는 것이라서요.
  - 카테고리 선택은 라디오 버튼을 칩 모양으로 꾸몄어요. 키보드 화살표 이동이 저절로 돼요.
- **영향**: 저장 형식은 바뀌지 않아서 `version`은 1 그대로예요.

## TL-014 개발용 `?today` 날짜 바꾸기

- **상태**: 채택 · 2026-11-11 (배포 버전에서 끌지 없앨지는 5단계에서 결정)
- **배경**: 이월·반복은 날짜가 바뀌어야 확인할 수 있어요. 기기 날짜를 바꾸는 건 번거롭고 다른 앱에도 영향을 줘요.
- **결정**

- **영향**: `createdAt`, `completedAt` 같은 시각은 실제 시각으로 저장돼요. 날짜를 **앞으로 되돌리면** 뒤 날짜에 만든 할 일은 "미래" 할 일이 되어 화면에 보이지 않아요(데이터는 남음).

## TL-015 반복·이월 구현에서 정한 세부 규칙

- **상태**: 채택 · 2026-11-11
- **배경**: PRD F7·F8과 TRD 5.2·5.9가 정하지 않은 경우가 몇 가지 있었어요.
- **결정**
  - **`runRollover`는 순수 함수**: 받은 상태를 복사(`structuredClone`)해서 고치고 `{ state, changed }`를 돌려줘요. 바뀐 게 없으면 저장·다시 그리기를 하지 않아요.
  - **규칙 저장도 `runRollover`로 오늘 몫을 만들어요.** 반복 규칙을 새로 만들거나, 고치거나, 다시 시작한 뒤에 한 번 불러요. 그래서 "저장 직후"와 "앱을 다시 열었을 때"의 결과가 항상 같아요. 오늘 몫을 이미 만들었으면(`lastGeneratedDate`가 오늘) 다시 만들지 않으니 "오늘 이미 생긴 할 일은 그대로"(PRD F8)도 지켜져요. 아직 오늘 몫이 없고 고친 규칙이 오늘에 맞으면 오늘 몫이 생겨요.
  - **`lastGeneratedDate`가 오늘보다 뒤면 만들지 않아요.** 기기 날짜가 거꾸로 가도 같은 규칙으로 두 번 만들지 않게요.
  - **여러 규칙이 같은 날 생기면 규칙 목록 순서대로** 이월 항목 바로 아래에 놓여요.
  - **"이전에 완료한 항목"을 완료 취소하면** 오늘 날짜로 옮기고 `carriedFrom`에 처음 날짜를 남긴 뒤 미완료 맨 아래에 놓아요. 지난 날짜에 미완료로 남겨 두면 화면 어디에도 안 보이기 때문이에요.
  - **시트 모드 이름**: TRD 5.9는 `+ 새 반복 일정`을 `mode: "add"`로 열고 '반복 안 함'만 뺀다고 했는데, 규칙 수정도 같은 시트를 쓰게 되어 `add / edit / rule-add / rule-edit` 네 모드로 나눴어요.
  - **반복 일정 관리 화면은 화면 전체를 덮는 대화 상자**(`role="dialog"`)예요. 그 위에 시트가 겹쳐 열릴 수 있어서, 시트는 열 때 뒤 화면들의 `inert` 상태를 기억했다가 닫을 때 되돌려요. Esc는 맨 위 화면만 닫아요.
- **영향**: 저장 형식은 그대로(`version: 1`)예요. `rules` 항목은 불러올 때 `id`, `text`, `repeat.type`을 검사하고, 깨져 있으면 TL-001처럼 백업 후 빈 상태로 시작해요.

## TL-017 드래그 정렬 구현 세부

- **상태**: 채택 · 2026-11-11
- **배경**: TL-004(Pointer Events로 직접 구현)와 TRD 5.6이 큰 방향을 정했어요. 만들면서 세부를 정했어요.
- **결정**
  - **필터 상태 이동은 `core/order.js`의 `moveVisible(list, isVisible, from, to)`**: 보이는 항목들의 원래 자리(인덱스)를 기억해 두고, 보이는 항목끼리만 섞은 뒤 그 자리에 다시 채워 넣어요. 안 보이는 항목은 자리도 순서도 그대로예요. 필터가 꺼져 있으면 `move`와 같아요.
  - **드래그와 키보드가 같은 `store.reorderTodo(id, toIndex)`를 써요.** `toIndex`는 화면에 보이는 미완료 항목 안에서의 위치예요.
  - **끄는 동안 다시 그리기 미루기**: 끄는 중에 자정 이월·`visibilitychange` 등으로 상태가 바뀌면 `render`가 끌던 요소를 없애 버려요. 그래서 `render`는 드래그 중이면 요청만 기억하고, 드래그가 끝나면 한 번 그려요.
  - **이동 범위**: 끄는 항목은 맨 위·맨 아래 항목의 가운데에서 반 칸까지만 갈 수 있어요. 가운데까지만 허용하면 맨 끝 자리로 옮길 수 없었어요.
  - **자동 스크롤 기준선**: 위쪽은 화면 맨 위가 아니라 **붙어 있는 헤더의 아래 끝**이에요. 헤더가 진행률·필터까지 품어서 키가 커서, 화면 맨 위를 기준으로 하면 손가락이 헤더 위로 올라가야만 스크롤돼요. 가장자리 72px 안에서, 가까울수록 빠르게(한 프레임 최대 16px) 움직여요.
  - **Esc로 취소**, 제자리에 놓으면 저장하지 않아요.
  - **키보드 결과 알림**: 화면에 안 보이는 `aria-live` 문단에 `"○○" 6개 중 4번째로 옮겼어요`를 넣고, 다시 그린 뒤 같은 손잡이에 포커스를 돌려줘요.
  - **손잡이 모양**: 점자 문자 `⠿`는 글꼴마다 다르게 보이거나 빠질 수 있어서 점 6개 SVG로 그렸어요. 화면 읽기 프로그램용 이름은 `순서 바꾸기: {내용}`이에요.
- **대안**: 끌 때마다 `render` → 끌던 요소가 사라지고 느려요(TL-007에서 이미 피하기로 함).
- **영향**: 저장 형식은 그대로(`version: 1`)예요.

## TL-018 PWA·다크 모드·마무리에서 정한 것

- **상태**: 채택 · 2026-11-11
- **배경**: 5단계(M8)에서 PWA와 다크 모드를 넣고, 배포 전 점검을 하면서 정한 것들이에요.
- **결정 — PWA**
  - **서비스 워커는 캐시 먼저 + `skipWaiting`/`clients.claim`**: 새 버전이 설치되면 기다리지 않고 바로 넘어가요. 열려 있던 화면은 이미 파일을 다 불러온 상태라 섞이지 않고, 다음에 앱을 열 때 새 파일이 보여요.
  - 설치할 때 `cache: "reload"`로 받아서 브라우저 HTTP 캐시의 옛 파일이 섞이지 않게 해요.
  - **찾을 때 주소 뒤 값(`?today=…`)은 무시**(`ignoreSearch`)하고, 처음 보는 페이지 이동은 `index.html`로 응답해요.
  - **옛 캐시는 `tm-cache-`로 시작하는 것만 지워요.** `yanniart.github.io`는 같은 계정의 다른 앱과 캐시 공간을 같이 써서, 남의 캐시를 지우면 안 돼요.
  - `tests/`는 캐시하지 않아요(항상 서버에서 받아서 테스트가 최신 코드로 돌게).
  - 등록은 `window.isSecureContext`일 때만(HTTPS·localhost). PC IP 주소(`http://192.168…`)에서는 조용히 건너뛰어요.
  - **아이콘**: `assets/icons/icon.svg`(둥근 사각형)와 `icon-maskable.svg`(바탕을 꽉 채우고 체크는 가운데 안전 영역 안)를 원본으로 두고, 헤드리스 Chrome으로 그대로 그려서 PNG(192, 512, maskable 512, iPhone용 180)를 만들었어요. 아이콘을 바꾸면 SVG를 고친 뒤 같은 방법으로 PNG를 다시 만들어요. iPhone은 manifest 아이콘 대신 `apple-touch-icon`을 써서 따로 넣었어요.
  - **개발 중 불편**: localhost에서도 캐시 먼저라 파일을 고쳐도 바로 안 보일 수 있어요. 개발자 도구의 "Update on reload"를 쓰도록 README에 적었어요. 개발 주소에서만 네트워크 먼저로 바꾸는 방법도 있지만, 그러면 개발 중에 오프라인 동작을 확인할 수 없어서 하지 않았어요.
- **결정 — 다크 모드**
  - `prefers-color-scheme: dark`에서 `base.css`의 변수만 바꿔요. 바탕 `#191919`, 카드 `#252525`, 선 `#373737`.
  - **파랑을 '면'과 '글자'로 나눴어요.** 버튼·체크처럼 칠하는 파랑(`--color-primary`)은 그대로 두고(흰 글자 4.57:1), 글자로 쓰는 파랑은 `--color-accent-text`(라이트 `#0075de` / 다크 `#5aa9ef`)와 `--color-accent-text-strong`(라이트 `#005bab` / 다크 `#7bbcf5`)으로 따로 둬요. `#0075de` 글자는 어두운 바탕에서 잘 안 읽혀요.
  - 삭제·이월 글자도 다크에서는 밝은 색(`#ff7b72`, `#ffb27a`)으로 바꿔요. 어두운 바탕에서는 옅은 그림자가 안 보여서 그림자를 조금 진하게 해요.
  - `theme-color`를 라이트·다크 두 개로 둬서 주소창 색이 바탕과 같아요.
- **결정 — 접근성 마무리** (화면마다 보이는 모든 글자의 실제 대비를 계산해서 찾았어요)
  - **입력창 테두리를 진하게**(`#dddddd` → `#8f8a85`, 다크 `#7d7d7d`): 입력창 테두리는 바탕과 3:1 이상이어야 하는데 디자인 문서의 색은 1.36:1이었어요(TL-016의 예외).
  - **할 일이 없는 카테고리 표시**(`업무 0/0`)를 `opacity: 0.6`으로 흐리게 하면 대비가 2.58:1까지 떨어져요. 글자는 흐린 글자색으로, 점만 흐리게 바꿨어요.
  - 종이색 바탕 위 파랑 글자(`반복 일정 관리에서 수정`)는 4.19:1이라 진한 파랑으로 바꿨어요.
- **결정 — `?today` (TL-014)**: **배포 버전에도 남겨 둬요.** localhost·사설 IP에서만 켜지므로 GitHub Pages 주소에서는 저절로 무시되고, 나중에 고칠 때 다시 테스트하기 편해요.
- **영향**: 앱 파일을 고치면 `sw.js`의 `CACHE_VERSION`을 올리고, 새 파일은 `APP_FILES`에 넣어야 해요(TRD 5.8). 저장 형식은 그대로(`version: 1`)예요.

## TL-019 화면 모드 전환 버튼과 반복 일정 버튼 아이콘

- **상태**: 채택 · 2026-11-11 (PRD v0.5, F12)
- **배경**: 다크 모드가 시스템 설정만 따라가서 앱 안에서 바꿀 곳이 없었어요. 사용자가 헤더에 전환 버튼을 원했고, 반복 일정 관리를 여는 ☰(메뉴 모양)도 무엇을 여는지 알기 어려웠어요.
- **결정**
  - 헤더 오른쪽에 **화면 모드 버튼**: 누를 때마다 시스템 설정 → 라이트 → 다크 → 시스템 설정. 아이콘은 **지금 모드**(반쪽 원·해·달)를 보여주고, 버튼 이름에 다음 모드를 적어요(`화면 모드: 라이트 (누르면 다크)`). 바꾼 결과는 화면 읽기 프로그램에 알려요.
  - 고른 값은 `settings.theme`(`"system" | "light" | "dark"`)에 저장해요. 예전 데이터에는 없어서 불러올 때 `"system"`으로 채워요. 필드를 더한 것이라 `version`은 1 그대로예요.
  - **다크 변수는 `:root[data-theme="dark"]` 한 곳에만** 둬요. TL-018에서는 `@media (prefers-color-scheme: dark)`로 켰는데, "직접 고름"까지 받으려면 같은 변수 묶음을 두 번 써야 해서, JS가 정한 결과(`light`/`dark`)를 `<html data-theme>`에 넣는 방식으로 바꿨어요. "시스템 설정"일 때는 `matchMedia`로 시스템 설정이 바뀌는 것도 바로 따라가요.
  - **깜빡임 방지**: 앱 JS는 모듈이라 화면을 그린 뒤에 실행돼요. 그래서 `index.html` 머리에 작은 인라인 스크립트를 두고, 저장된 값을 읽어 첫 화면을 그리기 전에 `data-theme`을 맞춰요. 이 스크립트는 `ui/theme.js`와 같은 규칙을 따라요(규칙을 바꾸면 두 곳 모두).
  - 직접 고른 모드에서는 주소창 색(`theme-color`)도 그 바탕색으로 바꾸고, 시스템 설정으로 돌아오면 원래 두 값(라이트·다크)으로 되돌려요.
  - **반복 일정 관리 버튼 아이콘**: ☰ 대신 **화살표 두 개가 도는 반복 모양**. 반복 할 일에 붙는 🔁 표시와 같은 뜻이라 무엇을 여는지 알 수 있어요. 요소 id도 `menu-button` → `rules-button`.
  - 좁은 화면(360px)에서 버튼이 두 개가 되니 제목이 두 줄로 밀렸어요 → 제목은 한 줄로 고정하고, 모자라면 날짜가 낱말 단위로 줄바꿈해요.
  - 순서 옮김 알림에 쓰던 화면 밖 알림 문단(`drag-status`)을 화면 모드 알림과 함께 쓰도록 `live-status`로 이름을 바꿨어요.
- **대안**: 버튼 두 개(라이트/다크 스위치)만 두기 → "시스템 설정 따르기"로 돌아갈 방법이 없어요.
- **영향**: 앱 파일이 바뀌어서 `sw.js`의 `CACHE_VERSION`을 `v2`로 올리고 `ui/theme.js`를 `APP_FILES`에 넣었어요.

## TL-020 + 버튼을 흑백으로

- **상태**: 채택 · 2026-11-11
- **배경**: 헤더의 아이콘 버튼(화면 모드, 반복 일정)은 흑백 선 아이콘인데, 떠 있는 + 버튼만 파랑이라 따로 놀았어요. 사용자가 헤더 아이콘과 비슷한 흑백으로 바꾸길 원했어요.
- **결정**
  - + 버튼 바탕은 글자색(`--color-ink`), + 는 바탕색(`--color-canvas`)으로 칠해요. 그래서 라이트는 **검은 원 + 흰 +**, 다크는 **흰 원 + 검은 +** 로 저절로 뒤집혀요. 누르면 `--color-ink-secondary`로 살짝 옅어져요.
  - + 선 굵기를 헤더 아이콘과 같은 2로(2.5 → 2), 크기 26px.
  - 대비: + 와 원 17.9:1(라이트)·15.0:1(다크), 원과 바탕도 같은 값이라 기준(3:1)을 넉넉히 넘어요.
  - TL-016의 "구조 색은 파랑 하나"의 예외예요. 디자인 문서에도 "라이트에서는 어두운 면, 다크에서는 밝은 면으로 뒤집는" 강조 면 예시가 있어서 같은 결이에요. 저장 버튼·체크·선택 표시 등은 파랑 그대로예요.
- **영향**: `sw.js`의 `CACHE_VERSION`을 `v3`으로 올렸어요.

## TL-021 검색·정렬·내보내기/가져오기·중복 확인·휴지통·성능

- **상태**: 채택 · 2026-11-11 (PRD v0.6, F13~F17, TRD v0.5 5.10~5.15)
- **배경**: 기능 6개를 한꺼번에 더하면서, 이미 있는 기능과 부딪히는 곳과 숨어 있던 위험을 먼저 점검했어요.

### 사용자에게 물어서 정한 것

| 문제 | 결정 |
|---|---|
| 정렬과 드래그 순서(F10)가 부딪힘 | **정렬은 보는 순서만** 바꾸고 손잡이를 숨김. 드래그 순서(`order`)는 남아서 '직접 정렬'로 돌아오면 그대로 |
| '완료 상태순'은 미완료/완료 구역이 이미 나뉘어 있어 의미가 없음 | 이 정렬을 고르면 **두 구역을 한 목록으로 합쳐** 미완료 먼저 |
| 가져오기를 지금 데이터와 어떻게 합칠지 | **전체 바꾸기** + 바꾸기 전 자동 백업(최근 3개) + 알림의 되돌리기 |
| 헤더에 버튼 자리가 모자람 | 🔍 검색과 ⋯ 더보기(정렬·데이터·휴지통)를 더하고, **날짜는 제목 아래 줄로** |

### 점검에서 찾은 위험과 처리

- **두 탭 동시 사용 시 덮어쓰기** (원래부터 있던 문제): 탭마다 메모리에 상태를 들고 있어서, 한 탭의 가져오기·복구를 다른 탭이 다음 저장 때 되돌려 버려요. → `storage` 이벤트로 다른 탭의 변경을 받아 상태를 갈아 끼움(`store.replaceState`).
- **저장 실패가 안 보임** (원래부터 있던 문제): `localStorage`가 가득 차면 콘솔에만 남았어요. 휴지통·백업으로 데이터가 커지면 생길 수 있어요. → `store.onSaveError`로 화면에 알림.
- **되살린 옛 할 일이 다시 사라짐**: 지난 날짜의 미완료 반복 할 일을 그대로 되살리면 다음 날짜 처리에서 또 지워져요. → 지난 날짜면 오늘로 옮기고 이월 표시.
- **검색 + 드래그**: 필터만 보던 `reorderTodo`가 검색까지 보도록 `isVisible`을 받게 함(화면에 보이는 조건과 같게).
- **한글 정규화**: Mac 등에서 자모가 풀린(NFD) 글자가 들어오면 같은 글자인데 검색·중복 확인에서 다르게 봐요. → 비교할 때 NFC로 맞추고, 저장할 때도 NFC로.
- **가져오기 파일은 밖에서 온 것**: 앱 데이터를 불러올 때보다 꼼꼼히 검사(날짜·카테고리·id 중복·길이·반복 설정·크기·버전). 화면에는 `textContent`로만 넣으니 HTML이 섞여도 실행되지 않아요.
- **브라우저에서만 나는 오류**: 디바운스 기본 타이머로 `setTimeout`을 객체 속성 그대로 불러서 "Illegal invocation"이 났어요(Node에서는 안 남). → 함수로 감쌈.
- **서비스 워커 파일 목록**: 새 파일 7개를 `APP_FILES`에 넣고 `CACHE_VERSION`을 `v4`로. 목록과 실제 파일을 비교해서 빠진 것이 없는지 확인(아이콘 SVG 원본 `icon-maskable.svg`는 화면에서 안 쓰여서 일부러 뺌).
- **개발 서버 한계(앱 문제 아님)**: 두 번째 탭과 서비스 워커 설치(파일 36개)가 겹칠 때 `python -m http.server`가 연결을 한 번 거절한 적이 있어요. 다시 해 보니 생기지 않았어요. 배포(GitHub Pages)에서는 해당 없어요.

### 정한 세부 규칙

- **검색**: 검색어는 저장하지 않음. 여러 낱말은 AND. 세 구역 모두 찾고 이전 완료 구역은 결과가 있으면 펼침. 진행률은 검색과 무관. 검색 중 드래그 허용(보이는 것끼리만).
- **정렬**: 생성일순은 먼저 만든 것부터(오름차순). 카테고리순은 업무→개인→공부, 같은 카테고리 안은 직접 정렬 순서. 목록 위 안내는 짧게 "○○순으로 보는 중 [직접 정렬로]"(드래그가 꺼지는 이유는 화면 읽기 프로그램용 이름과 더보기 설명에).
- **중복 확인**: 막지 않고 알리기만. 오늘 **미완료**만 비교(완료한 일은 다시 하는 일일 수 있어서). 반복을 고르면 같은 이름의 반복 일정과 비교. 입력이 멈출 때 한 번(디바운스).
- **휴지통**: 할 일과 **반복 일정도** 넣어요(지운 것은 모두 되살릴 수 있게). 30일·100개. 지운 직후 6초 동안 '되돌리기'. '완료한 항목 모두 지우기'는 한 묶음.
- **가져오기 백업 키**: `task-manager.backup.import.<시각>`, 최근 3개만. 백업할 공간이 없으면 알림의 되돌리기만 가능하다고 알려요.
- **알림(토스트)**: 한 번에 하나, 버튼이 있으면 6초·없으면 4초. 글자색과 바탕색을 뒤집은 흑백(+ 버튼과 같은 결)이라 라이트·다크 모두 대비가 높아요.
- **검색 강조 색**: 노랑 형광펜 대신 옅은 파랑 바탕 + 파랑 밑줄 (TL-016 "구조 색은 파랑 하나").

### 성능

- 바꾸기 전 측정(300개, CPU 4배 느리게): 체크 72ms, 한 칸 옮기기 64ms, 필터 48ms. 원인은 바뀔 때마다 모든 줄 요소를 새로 만들고 목록 전체를 갈아 끼우는 것.
- 처리: 줄 요소 재사용(내용이 같으면 그대로), 자리가 바뀐 요소만 옮기기, 반복 일정·휴지통 목록은 바뀔 때만, 검색·중복 확인 디바운스, 드래그 중 바뀐 항목만 스타일 변경.
- 결과: 체크 17ms, 한 칸 옮기기 9ms, 필터 31ms, 검색 글자 입력 1ms(빠르게 5글자 → 다시 그리기 1번). 측정 방법은 TRD 5.14.
- 하지 않은 것: `content-visibility`(화면 밖 줄 그리기 생략)는 드래그가 줄 위치를 미리 재는 방식과 부딪혀서 빼 두었어요. 저장(`JSON.stringify`)은 300개에서도 몇 ms라 디바운스하지 않았어요(앱을 닫을 때 마지막 변경을 잃을 위험이 더 커요).

- **대안**: 가져오기 '합치기' → 같은 할 일이 두 번 생기기 쉬워서 이번에는 '바꾸기'만. 정렬이 순서를 덮어쓰기 → 드래그로 정한 순서를 잃어서 뺌.
- **영향**: 저장 형식은 필드만 늘어서 `version` 1 그대로(`trash`, `settings.sort`). `sw.js` `CACHE_VERSION` `v4`.

## TL-023 키워드 기반 카테고리 자동 분류

- **상태**: 채택 · 2026-11-11 (PRD v0.8 F18, TRD v0.7 5.16)
- **배경**: 할 일을 적을 때마다 카테고리 칩을 고르는 게 번거로워요. 내용 속 낱말로 대부분 짐작할 수 있어요("회의" → 업무).
- **결정**
  - **언제**: 추가할 때만(할 일 추가, 새 반복 일정). 수정 시트에서는 하지 않아요 — 이미 있는 할 일의 카테고리가 사용자 모르게 바뀌면 안 돼서요.
  - **고르기만, 막지 않기**: 칩을 골라 주고 이유를 칩 아래에 적어요. 사용자가 칩을 한 번이라도 누르면 그 시트에서는 자동 분류를 멈춰요(직접 고른 것이 우선).
  - **키워드가 사라지면 되돌리기**: 처음 카테고리로 돌아가요. 안 그러면 "회의"를 지웠는데도 업무가 남아요.
  - **저장 직전에 한 번 더**: 디바운스를 `flush`해서 입력하자마자 저장해도 적용돼요.
  - **기본값(lastCategory)을 안 바꿈**: 자동으로 고른 카테고리까지 기억하면 다음 할 일(키워드 없음)의 기본값이 엉뚱하게 바뀌어요. 직접 고른 값만 기억해요.
  - **매칭 규칙**: 정리한 글자(NFC·소문자·공백)에서 부분 일치. 여러 개면 긴 키워드 → 앞에 나온 키워드 → 업무·개인·공부 순서. 형태소 분석 같은 건 하지 않아요(라이브러리 없음 원칙, 이 정도 목록에는 충분).
  - **기본 키워드**: 카테고리마다 16개, 모두 두 글자 이상(한 글자는 "책상"의 "책"처럼 엉뚱하게 걸려서), 카테고리끼리 겹치지 않게. 테스트로 확인해요.
  - **저장**: `settings.autoCategory = { enabled, keywords }`. `keywords: null`이면 기본 키워드를 따라가서, 한 번도 안 고친 사람은 앞으로 기본 키워드가 좋아지면 그대로 받아요. 처음 고칠 때 기본값을 복사하고 그 카테고리만 바꿔요.
  - **키워드 편집**: 더보기 맨 위. 쉼표로 구분, 다른 곳을 누르거나 Enter를 치면 저장하고 정리된 모양으로 다시 보여줘요(공백·빈 것·중복·20자 초과 정리, 카테고리당 50개). 키워드가 많아도 다 보이게 한 줄 칸 대신 여러 줄 칸. 같은 키워드가 여러 카테고리에 있으면 어느 쪽이 쓰이는지 알려줘요.
  - 안내 문구의 조사는 받침에 맞게(`withParticle`): "업무를", "개인을", "'영어'는 … 업무가 우선이에요".
- **대안**: 칩은 그대로 두고 "업무로 바꿀까요?" 제안만 → 한 번 더 눌러야 해서 덜 편해요. 저장 뒤에 바꾸기 → 사용자가 고른 칩과 다르게 저장돼서 헷갈려요.
- **영향**: 저장 형식은 필드만 늘어서 `version` 1 그대로(예전 데이터는 켜짐 + 기본 키워드). 가져오기·내보내기에 함께 들어가요. 새 파일 `core/classify.js`, `sw.js` `CACHE_VERSION` `v6`(앱 파일 38개).
