  - `tests/run-core.mjs`: core 테스트를 Node에서 (`--tz=`로 시간대 바꾸기)
  - `tests/store.test.mjs`: store·storage 확인
  - `tests/e2e/run.mjs`: 브라우저 확인 실행기(Chrome·Python 찾기, 서버 없으면 띄우기, 단계 고르기, 합계) + `harness.js`, `audit.js`, `steps/02~08`, `steps/perf.js`
- 기술로그 [TL-024](tech-log.md#tl-024), TRD 8장·README·CLAUDE.md에 실행 방법

### 확인 결과

| 무엇 | 결과 |
|---|---|
| `node tests/run-core.mjs --tz=…` 7개 시간대 (서울, LA, UTC, 오클랜드, 세인트존스, +14, −11) | 78개씩 모두 통과 ✅ |
| `node tests/store.test.mjs` | 23개 모두 통과 ✅ |

### 문제와 해결

- **시간대 확인이 사실은 안 되고 있었음**: Windows(Git Bash)에서 `TZ=America/Los_Angeles node …`가 무시되고 계속 서울 시간으로 돌았어요. 1~3단계 기록의 "미국 시간대로도 통과"는 그때 실제로 확인된 게 아니었어요. 실행 중에 `process.env.TZ`를 바꾸는 `--tz=` 옵션으로 고치고, 이번에 7개 시간대에서 실제로 통과하는 것을 확인했어요.
- 단계마다 같은 Chrome 프로필 폴더를 지우고 다시 쓰다가 `EPERM`(Windows에서 Chrome이 잠깐 파일을 잡고 있음) → 단계마다 새 폴더, 끝에 정리
- 5단계 파일에 `audit.js`와 같은 대비 계산 코드가 남아 있어 두 번 선언됨 → 5단계 쪽을 지움
- 8단계에서 개발 서버가 연결을 한 번 거절(이미 알던 현상) → 다시 돌리니 통과
- 문서에 "약 10분"이라고 적었는데 실제로는 약 1분 반 → 고침

## 2026-11-11 (수) — 키워드 기반 카테고리 자동 분류 (PRD v0.8, F18)

### 한 일

- 추가 시트에서 입력이 멈추면 내용 속 키워드로 카테고리 칩을 골라 주고, 칩 아래에 이유를 알려줘요("'회의' 키워드로 업무를 골랐어요").
- 직접 누른 칩이 우선, 수정 시트에서는 안 함, 키워드가 사라지면 원래대로, 입력하자마자 저장해도 적용, 자동 선택은 기본 카테고리를 안 바꿈
- 더보기 맨 위 "자동 분류": 켜기·끄기 스위치, 카테고리별 키워드(여러 줄 칸), 겹치는 키워드 안내, 기본값으로 되돌리기
- 기본 키워드 카테고리마다 16개(두 글자 이상, 겹침 없음)
- 새 파일 `js/core/classify.js`, 조사 함수 `withParticle`(core/text.js), `sw.js` `v6`(앱 파일 38개)
- 문서: PRD v0.8(F18), TRD v0.7(5.16, `settings.autoCategory`), 기술로그 [TL-023](tech-log.md#tl-023)

### 확인 결과

- core 테스트 **78개**(새로 11개: 자동 분류 10, 조사 1)
- 자동 분류 브라우저 확인 **23개** + 기존 확인 2~7단계(27 + 33 + 25 + 13 + 15 + 49) = **185개 모두 통과**

| 확인 항목 | 결과 |
|---|---|
| 입력이 멈추면 분류 + 안내, 내용을 바꾸면 다시 분류, 키워드가 없어지면 원래 카테고리로 | ✅ |
| 입력하자마자 저장해도 적용, 자동 선택은 다음 기본값을 안 바꿈 / 직접 고른 값은 기억 | ✅ |
| 칩을 먼저 누르거나 자동 선택 뒤 누르면 그게 우선, 이후 입력에도 안 바뀜 | ✅ |
| 수정 시트는 자동 분류 안 함, 새 반복 일정에서는 동작 | ✅ |
| 더보기: 키워드 고치기(정리해서 저장, 다른 카테고리는 기본값), 고친 키워드 바로 사용, 겹침 안내, 끄기(새로고침 유지), 되돌리기 | ✅ |
| 예전 데이터(설정 없음)도 켜짐 + 기본 키워드로 동작 | ✅ |
| 360px 더보기 가로 스크롤 없음, 칸 44px·16px / 라이트·다크 글자 대비 | ✅ |

### 문제와 해결

- 안내 문구가 "업무을(를)"처럼 어색함 → 받침을 보고 조사를 고르는 `withParticle` 추가
- 키워드 칸이 한 줄이라 긴 목록이 잘려 보임 → 여러 줄 칸으로
- 스위치 손잡이에 흰색을 직접 적었던 것 → 색 변수(`--color-on-primary`)로
- 확인 중 개발 서버(`python -m http.server`)가 연결을 한 번 거절함 → 다시 돌리니 통과 (앱 문제 아님, TL-021과 같은 현상)

### 알아 둘 점

- 낱말 일부만 같아도 걸려요(부분 일치). 예: 업무 키워드 "회사"는 "회사원 친구 생일"에도 걸려요(이 경우는 같은 길이 "생일"보다 앞에 있어서 업무). 직접 칩을 누르면 바로잡혀요.

## 2026-11-11 (수) — 정렬을 아이콘 메뉴로 옮김 (PRD v0.7)

### 한 일

- 사용자가 준 스크린샷의 자리(필터 탭 아래 오른쪽)에 **정렬 아이콘(⇅) + 작은 메뉴**를 두고, 더보기 화면에서는 정렬을 뺐어요.
- 직접 정렬이면 아이콘만, 다른 정렬이면 "⇅ 생성일순"처럼 파랑 + 이름. 예전 정렬 안내 상자는 없앰
- 검색 결과 수는 같은 줄 왼쪽으로
- 새 파일 `js/ui/sort-menu.js`, `sw.js` `v5`(앱 파일 37개), PRD v0.7, TRD v0.6, 기술로그 [TL-022](tech-log.md#tl-022)

### 확인 결과

- 새 기능 확인 49개(정렬 아이콘·메뉴 11개 포함) + 기존 2~6단계 113개 = **162개 모두 통과**
- 아이콘 위치(필터 탭 아래·목록 위·오른쪽 끝·44px), 메뉴 열기·체크·↓ 키·Esc·바깥 누르기, 정렬 4가지, 새로고침 유지, 직접 정렬로 돌아가면 드래그 순서 그대로, 더보기에는 데이터·휴지통만, 라이트·다크 대비

### 문제와 해결
